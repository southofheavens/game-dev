# Проект «Масштаб»

2D пазл-платформер на Unity, в котором персонаж умеет на лету менять
размер. От размера зависит почти всё: масса, скорость, дальность прыжка,
какие двери откроются, какие стены сломаются, а какие — наоборот, не дадут
пройти.

Учебный проект — здесь обкатываются нетривиальные механики (сохранение
импульса при трансформации, резонанс, скрытые пути, адаптивная камера,
энергия) и собирается всё это через Cinemachine, ParticleSystem и
ScriptableObject.

## Запуск

1. Поставьте Unity Hub и редактор **Unity 2022.3 LTS** (любой подверсии,
   `2022.3.20f1` подойдёт). Дополнительные модули не нужны.
2. В Unity Hub: **Open → Add project from disk** → папка `ProjectScale`.
3. Дождитесь импорта пакетов (Cinemachine, URP, VFX Graph, TMP, Input
   System) — это разово, минуту-две. Если предложит **Import TMP
   Essentials** — соглашайтесь.
4. Дальше всё происходит само: создаётся сцена `Assets/Scenes/MainLevel.unity`,
   в ней один объект `Bootstrap`, в консоли — `[ProjectScale] Проект готов.
   Нажмите Play.`
5. Жмите **▶ Play**. Сначала откроется меню выбора уровня, после клика
   `LevelGenerator` соберёт уровень программно — никакого ручного drag&drop.

## Управление

| Клавиша                | Действие                            |
| ---------------------- | ----------------------------------- |
| `A` `D` `←` `→`        | Бег                                 |
| `Space` `W` `↑`        | Прыжок (с coyote-time и jump-buffer)|
| `1` / `2` / `3`        | Малый / Нормальный / Большой размер |
| `Q` / `E`              | Размер на шаг меньше / больше       |
| `Esc`                  | Вернуться в меню                    |

Каждая трансформация тратит энергию (полоса слева сверху). Энергии не
хватает — превращение не сработает. Восполняется со временем, поэтому
маршрут приходится планировать заранее.

## Механики

**Динамический масштаб.** Три состояния (`Small / Normal / Big`) живут как
`ScriptableObject`-профили (`Assets/Scripts/Core/ScaleProfile.cs`). Каждый
профиль задаёт размер, массу, гравитацию, скорость, прыжок, цвет и
стоимость трансформации. Small быстрый и прыгучий, Big медленный, но
тяжёлый и пробивной.

**Сохранение импульса.** При трансформации скорость не сбрасывается, а
пересчитывается с бонусами (см. `PlayerScaleController.ComputePreservedVelocity`):
сжался в воздухе — Y-буст, как катапульта; вырос в воздухе — X-буст,
длинный прыжок. Так трансформация становится не утилитой, а трюком.

**Резонанс.** `ResonantObject` реагирует только на `resonanceFrequency`
из текущего профиля. На уровне есть кристаллы, которые «откликаются»
только на конкретный размер.

**Скрытые пути и узкие проходы.** `HiddenPath` показывает мост только в
нужном размере; `SizeGate` физически не пропускает запрещённые размеры.

**Плита давления — Goldilocks.** `PressurePlate` срабатывает не от
«тяжести», а от диапазона масс. Серая плита — Big-only, жёлтая —
только Normal: Small слишком лёгкий, Big её перевешивает.

**Big-Breakable.** Оранжевые стены ломаются ударом в Big-форме и
рассыпаются на осколки.

**Стена шипов (`PursuingSpikes`).** Слева ползёт стена смерти. Стоять и
думать долго не получится. Игрок при беге быстрее стены, так что в
движении вы её обгоняете без проблем.

**GD-секция.** Финал уровня — узкие плавающие платформы над пропастью
в шахматном ритме. Big тут не пройдёт: его прыжок всего ~3.6 единиц при
гэпах в 5+. Перед секцией обязательно переключиться в Normal или Small.

**Адаптивная камера.** `AdaptiveCameraController` подстраивает
ортосайз `CinemachineVirtualCamera` под размер игрока (4.5 / 6.5 / 9.0)
и встряхивает камеру при трансформации.

**Энергия и события.** `EnergySystem` хранит запас и регенерацию.
`GameEvents` — статическая шина (`OnScaleChanged`, `OnEnergyChanged`,
`OnCollectibleGathered`, `OnLevelCompleted`, `OnPlayerDied`). Через неё
общаются UI, эффекты и геймплей.

**Эффекты.** `PlayerTrail` (хвост за игроком, цвет от размера),
`ImpulseRouter` + Cinemachine Impulse (тряска камеры), `ScreenFlash`
(вспышка при трансформации/смерти, на `unscaledDeltaTime`), `PulseSprite`
(пульсация платформ и финиш-флага), фоновое звёздное поле и слоумо при
смерти на 0.45 сек.

**Перезагрузка при смерти.** `GameManager.HandlePlayerDied` через
`SceneManager.LoadScene` пересобирает уровень с нуля: ворота закрываются,
стены восстанавливаются, кристаллы возвращаются, шипы уезжают на старт.
Никакого ручного reset-а по объектам — единая точка правды в `LevelGenerator`.

## Три уровня сложности

Все уровни используют один набор пазлов, но различаются параметрами в
`Core/LevelConfig.cs`:

| Уровень              | Шипы (ед/сек) | GD-секция                  | Доп. препятствия           |
| -------------------- | ------------- | -------------------------- | -------------------------- |
| **L1: Знакомство**   | 1.2           | 8 шт., ширина 2.0, гэп 5.0 | —                          |
| **L2: Усложнение**   | 1.7           | 9 шт., ширина 1.5, гэп 5.0 | + Big-стена (x ≈ 40)       |
| **L3: Мастер**       | 2.2           | 10 шт., ширина 1.2, гэп 5.5| + Big-стена + столб шипов  |

Столб шипов на L3 (`top y = −0.2`) специально настроен так, что Big в
него упирается даже в апексе прыжка, а Normal/Small — пролетают. Это
заставляет переключаться туда-сюда: сломал Big-стену → ужался для
столба → снова Big для финальной стены. Энергобюджет начинает кусаться.

После прохождения уровня `GameManager` через 2 сек переходит к
следующему. После последнего — экран «ИГРА ПРОЙДЕНА» и возврат в меню.
В любой момент `Esc` — назад в меню.

## Архитектура запуска

- **`Editor/AutoFirstOpen.cs`** — на первом открытии проекта вызывает
  `LevelBuilder.BuildBootstrapScene()`, который создаёт сцену с одним
  объектом `Bootstrap` и регистрирует её в Build Settings.
- **`RuntimeBootstrap.Awake()`** — точка входа. Если `LevelManager.LevelSelected`
  ещё не выставлен, рисует меню (`LevelGenerator.BuildMenu`); иначе собирает
  уровень (`LevelGenerator.BuildEverything`) согласно `LevelManager.Current`.
- **`LevelGenerator`** генерирует всё в рантайме: окружение, игрока,
  Cinemachine-камеру, головоломки, коллектаблы, UI, starfield, шипы и
  GameManager. Спрайты и профили создаются in-memory.

Профит — каждый запуск собирает уровень с нуля, состояние редактора ни
на что не влияет.

```
ProjectScale/
├── Assets/
│   └── Scripts/
│       ├── Core/           // ScaleState, ScaleProfile, GameEvents, GameManager,

│       ├── Player/         // PlayerScaleController, PlayerMovement, PlayerInput, EnergySystem
│       ├── Camera/         // AdaptiveCameraController
│       ├── Interactables/  // ResonantObject, HiddenPath, SizeGate, PressurePlate,

│       │                   // LevelFinish, Hazard
│       ├── UI/             // GameHUD, LevelSelectMenu
│       ├── Effects/        // PlayerTrail, ImpulseRouter, ScreenFlash, PulseSprite,
│       │                   // TransformVfxFallback
│       └── Editor/         // LevelBuilder, AutoFirstOpen
├── Packages/manifest.json  // Cinemachine, URP, VFX Graph, TMP, Input System
└── ProjectSettings/
```
